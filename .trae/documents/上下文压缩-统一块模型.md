# 上下文压缩 · 统一块模型整合方案（ACP 与通用 compact 的块一致化）

> 目标：消除「通用 compact 的块」与「ACP 的块」两套互不感知的结构，让**所有折叠窗口（无论来自 ACP 还是通用 compact）都成为 `session.blocks` 的一致稳定节点**，从而修复三处断裂：① 请求瘦身漏掉 ACP 折叠；② 高频多块不可定位/不可重建历史；③ revert 找不到 boundary、无法只回退最近消息。

- 关联文档：`docs/context-compression-plan.md`（D2/D4 的落地缺口）、`docs/development-log.md`（续 106-109）、`.trae/documents/会话上下文压缩-阶段2-RouteB.md`
- 性质：整合方案（先对齐、后实施）。**已落地**（见 `docs/development-log.md` 续 110），下表与改动清单对应现状。
- 涉及包：`session` / `workspace` / `core` / `plugins/acp-context` / `revert` / `cli`

---

## 1. 现状与断裂（代码勘察结论）

存在两套并行、互不感知的"块"：

| 套 | 生成者 | 落点 | 消费方 |
|----|--------|------|--------|
| A | 通用 compact | `session.blocks` + `.cmp.orig/{blockId}.json` | 视图 `renderBlocksAsMessage`、loader、`reconstructHistory`、cli `loadFullHistory` |
| B | ACP（`runPreModel`/`runCompacting`） | 仅自身 `meta[acp.v1]` + `meta[acp.archive.v1]` | 仅 ACP 的 `decompress`/检索 |

由此导出三处断裂：

1. **块不一致（D4 未落地）**：`CompactionBlock`（[session/src/index.ts#L165-L184](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/session/src/index.ts)）无来源标记；ACP 从不写 `session.blocks`（[acp-context/src/index.ts 仅写 meta](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/plugins/acp-context/src/index.ts)）。`renderBlocksAsMessage`（[L248-L261](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/session/src/index.ts)）只会渲染 A 套 → B 套折叠对请求瘦身隐形。
   - 后果：`query`/`queryStream` 的精简视图（[core/src/index.ts#L1365-L1374](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/core/src/index.ts)）只体现 A 套折叠；ACP 长期会话的 B 套折叠完全不进入视图与历史重建。
2. **高频多次折叠不可定位**：`runPreModel` [每轮调 `engine.processTurn`](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/plugins/acp-context/src/index.ts)（超阈值即折块），一次长对话累积多个 B 套块；它们不构成稳定节点 → `reconstructHistory`（[session L273-L298](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/session/src/index.ts)）、cli `loadFullHistory`、revert 均读不到。
3. **revert 无法只回退最近消息**：revert `stage` 靠 `session.messages.findIndex/some(boundaryId)` 找边界、`collectSnapshotMap` 从 boundary+1 向近期扫（[revert/src/index.ts#L108-L118、L156-L191](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/revert/src/index.ts)）。boundary 一旦被折叠出近期 messages → `findIndex` 失败抛 `RevertError`；即便不抛，boundary 更早被折叠的 assistant 快照引用也漏掉。→ "回退最近一条/几条"在折叠后不可靠。

**根因**：A/B 两套块的生成、落点、消费方完全分离，计划文档 D4"断点索引复用 ACP 的 messageRefs/blocks"未落地。

## 2. 目标与设计决策

### D1. 统一块模型：所有折叠都进 `session.blocks`
- `CompactionBlock` 增加 `source?: 'generic' | 'acp'` 与可选 `archiveRef?: string`（原文取回方式，见 D3）。
- ACP 折叠出块时，除写 `meta[acp.v1]` 外，**同步追加一个带 `source:'acp'` 的块到 `session.blocks`**。
- 通用 compact 产块仍带 `source:'generic'`。
- 收益：`renderBlocksAsMessage`/`reconstructHistory`/loader/revert **只读同一份 `session.blocks`**，视图瘦身与历史重建覆盖全部折叠。

### D2. 归属判定：避免同一窗口双块
- 一段窗口归谁折叠，用既有 `coveredMessageIds`（ACP）与 `windowHandled` 判定。
- 时序：core `compact()` 先触发 `session.compacting`（ACP `runCompacting`）→ 若 ACP 用 `windowHandled=true` 认领该窗口并产 `source:'acp'` 块 → core **跳过**通用 compact 对该窗口再次产块与 `.cmp.orig` 归档（消除"重复归档"冗余，修复续 109 遗留问题）。
- 若窗口未被 ACP 认领 → core 走通用 compact 产 `source:'generic'` 块 + `.cmp.orig`。
- 双块重叠防护：ACP 折叠前仍用 `coveredMessageIds` 过滤"尚未覆盖"片段（现状已做，保留）。

### D3. 原文取回单一途径（归并 origKey）
- `CompactionBlock.origKey` 现有语义保留；新增当 `source:'acp'` 时 `archiveRef` 指向 ACP 归档 key（`meta[acp.archive.v1]` 或 `.cmp.orig`）。
- `SessionOriginalStore` 扩展可选 `loadRef(sessionId, ref)`，供 `reconstructHistory` 对 `source:'acp'` 块经 ACP 归档取回原文，避免原文双写（meta + `.cmp.orig`）。
- 目标：**同一窗口的原文只落一处**，loader/revert 统一经 `origKey` 或 `archiveRef` 取回。

### D4. revert 走全文回溯定位 boundary
- revert `stage`/`collectSnapshotMap` 不再依赖 `session.messages` 直接 `findIndex`，改为：
  1. 经 `reconstructHistory`（含 loader 还原归档原文 + 近期）得全文；
  2. 在**全文**里定位 `boundaryMessageId`；
  3. 从 boundary 之后收集带 `meta.snapshot` 引用的 assistant 消息（含被折叠块内的）。
- 保证边界无论折叠与否，"只回退最近消息"始终可用。
- 依赖注入：revert 插件需拿到 `session` 视图/loader（经 cli 注入的原 `harness.session.flushHistory`/`loadFullHistory`），当前 revert 已注入 `session`（[revert/src/index.ts 构造依赖](file:///Users/oyoungy/Documents/project/XiaoZhi-new/packages/revert/src/index.ts)）。

### D5. 兼容与未变
- ACP 停用：通用 compact 独立产出 `source:'generic'` 块，行为同现状（Route B 已验收）。
- ACP 启用：仅增加"同步落 session.blocks + 避免重复归档"，语义不倒退。
- 不影响 `.cmp.orig` 既有文件格式（向后兼容已压缩会话）。
- 请求消耗：`renderBlocksAsMessage` 仍以 `blocks` 生成摘要占位，token 上限约束沿用（≤300 语义，遇 ACP/通用大量块时取折中或截断）。

## 4. 实施顺序

按依赖序，每包 typecheck + 单测 + 更新开发日志 + commit：

1. **plugin + session**：`CompactionContext.blocksPatch`；`CompactionBlock.source/archiveRef`；`SessionOriginalStore.loadRef`；`buildResolveBlock` 辅助（含单测）。
2. **workspace**：`createWorkspaceOriginalStore.loadRef`（单测）。
3. **core**：`compact()` 消费 `windowHandled` 跳重复归档 + 产 `source` 块；新增单测（ACP 认领时不双块/.cmp.orig、未认领走 generic）。
4. **acp-context**：`runCompacting`/`runPreModel` 补写 `source:'acp'` 块；单测（折叠→session.blocks 出现一致块、幂等不重复）。
5. **revert**：全文回溯定位 boundary；单测（边界在折叠块内仍可"回退最近消息"）。
6. **cli**：注入 `getFullHistory`；`loadFullHistory` 兼容双源；手测（长会话折叠后 revert 最近消息）。
7. 回归：全仓 typecheck + `bun test`；更新 `docs/development-log.md`（续 110）与 `docs/context-compression-plan.md`（D2/D4 落地、状态收口）。

## 5. 验证

- **单元**：
  - session：`CompactionBlock.source/archiveRef` 序列化；`buildResolveBlock` 按 source 分派 origKey/archiveRef；`reconstructHistory` 混合块还原全文。
  - core：`compact()` 在 `windowHandled=true` 时不产 `.cmp.orig`、不追加 generic 块；`windowHandled` 缺省/未设时走原逻辑。
  - acp-context：折叠后 `session.blocks` 出现 `source:'acp'` 块；二次折叠幂等不重复；`windowHandled=true` 且 `blocksPatch` 回传。
  - revert：boundary 在近期 messages 内 & 在折叠块内两种情形均能"只回退最近消息"。
- **回归**：ACP 停用时通用压缩行为零变化（既有 Route B 用例）；revert/core/acp 既有用例不破。
- **手测**：长会话（多次折叠）后——`renderBlocksAsMessage` 摘要含全部折叠；`/history`/`loadFullHistory` 还原全量；`/revert` 对最近消息的边界（含跨折叠）可回退。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| ACP 每轮补写 `session.blocks` 写入频繁 | 块 id 覆盖合并 + 按需持久化（`stateSnapshot` 判变，复用续 104 增量策略）；非首轮 performance 敏感路径走"折叠时才落、不折叠不写" |
| A 套与 B 套对同一窗口归属冲突 | 统一路由到 `windowHandled` + `blocksPatch`：窗口归 ACP 则 core 让位，避免双块/双归档 |
| revert 依赖 `flushHistory`/`loadFullHistory` 异步化 | revert 构造注入 `getFullHistory`（cli 已具备单测覆盖的 `loadFullHistory`），缺失时回退现状并告警 |
| `session.blocks` 与 `meta[acp.v1]` 双源漂移 | 以 `session.blocks` 为唯一历史重建/回溯源；ACP 归档仅作原文取回（`archiveRef`），`meta[acp.v1]` 仍供 ACP 自身 messageRefs 判定 |
| 向后兼容既有 `.cmp.orig`/已压缩会话 | `source` 可选、缺省视为 `generic`；既有块不带 `source` 也不会报错 |
