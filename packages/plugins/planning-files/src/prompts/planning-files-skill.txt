# 文件化持久规划（`.planning/`）

计划不放在对话里，放在**磁盘上** —— 这样 `/clear`、重启、崩溃、上下文压缩之后它都还在。
每轮开始前，宿主会把当前计划的一小段摘要注入到上下文末尾（`===BEGIN PLAN DATA===` 块），
你不需要背计划，但**需要维护它**。

## 三个文件

| 文件 | 作用 | 纪律 |
|---|---|---|
| `.planning/task_plan.md` | 阶段 + 复选框 —— **进度的唯一权威** | 改完必须 `/plan-attest` |
| `.planning/findings.md` | 调研笔记：事实 + 证据位置 | 写事实要带 `文件:行` 或实测输出；推测必须标注为推测 |
| `.planning/progress.md` | 追加式进度日志（怎么走到这里的） | **只追加，不重写历史行** |

## 什么时候动它

- **接到多步任务**：先用 `/plan <一句话目标>` 初始化，再把阶段与条目填进 `task_plan.md`
  （用 `write_file`；阶段写成 `## Phase N: 标题`，条目写成 `- [ ]` / `- [x]`）。
- **完成一个条目**：把 `- [ ]` 改成 `- [x]`，并往 `progress.md` 追加一行（带时间与证据）。
- **得到关键事实 / 做了决策**：写进 `findings.md`，别留在对话里 —— 对话会被压缩。
- **改完 `task_plan.md`**：立刻 `/plan-attest` 重新认证。否则下一轮注入会变成
  `[PLAN TAMPERED]` 告警块、**计划正文不再注入**（你会失去计划可见性，直到重新认证）。

## 注入块怎么读

```
===BEGIN PLAN DATA===
计划: .planning/task_plan.md
目标: …              ← 目标行（防 goal drift 的锚）
当前阶段: Phase 2: 实现（进行中 3/5）
下一步: …            ← 当前阶段里第一条未完成项
完成度: 3/7
认证: sha256:…（已认证）
===END PLAN DATA===
```

看到 `[PLAN TAMPERED]` ⇒ 计划文件被改动而未被认证。**先与用户确认这次改动是不是你写的**；
确认无误后用 `/plan-attest` 重新认证，然后继续。

## 命令

- `/plan [目标]` —— 初始化三文件并展示；`--force` 用模板覆盖（会丢内容，需先确认）；`--use <名>` 切换多计划
- `/plan-status` —— 阶段 / 完成度 / 下一步
- `/plan-attest` —— 锁定当前 `task_plan.md` 的哈希（`--clear` 清除认证）
- `/plan-doctor` —— 自检（文件、解析、认证、注入状态）
- `/plan-complete` —— 完成度；全部勾选时提示可以收尾

## 两条容易犯的错

1. **只勾选框、不写 progress** ⇒ 下次（或压缩后）没人知道"怎么走到这里的"。
2. **改了计划不 attest** ⇒ 注入被拒绝，模型看不见计划，行为退化成"没有计划"。
