SubagentTool 让主 Agent 能派出子 Agent 执行独立任务。

## 前台 / 后台决策规则

- 需要子 Agent 的结果才能继续下一步 → **前台（默认）**：子 Agent 执行完成后，最终回复作为工具结果返回。
- 子 Agent 有独立工作可并行、或当前流程无需等待其结果 → **后台（runInBackground: true）**：立即返回 taskId，子 Agent 在后台异步执行。
- 多次 runInBackground=true 调用会在后台并行执行多个子 Agent，互不阻塞。

## 后台模式（runInBackground: true）

立即返回 taskId，子 Agent 在后台异步执行。执行完成后：
1. 通过 Bus 事件 subagent.completed / subagent.failed 推送（带 taskId）
2. 自动向父会话注入 <task-notification> 通知（下一轮推理开始时可见），无需主动查询

## 怎么写 prompt（上下文传递清单）

子 Agent **看不到本会话**：它拿到的只有你写进 `prompt` 的这一段。上下文没给足，返回的就是一段正确的废话。派工前逐项自检：

1. **目标**：一句话说清要交付什么（"列出 X 的三处调用点" 而不是 "看一下 X"）。
2. **路径/符号**：相关文件、目录、函数名、行号。让它直接定位，不要让它先全仓找。
3. **已知结论与约束**：你已经查到的、它不必重查的（"已确认 A 由 B 调用，只需核对 C"）；以及必须遵守的约束（不许改文件、只用只读工具）。
4. **验收标准**：怎样算完成（返回格式、需要哪些字段、要覆盖哪些点）。
5. **范围边界**：明确不要做什么（"不要改代码"、"不要顺带重构"、"不要评价整体设计"）。

反例（禁止）：「看一下 packages/core 有什么问题」「帮忙优化一下」—— 缺目标、缺路径、缺验收标准。

续接（sessionId）时只写**增量要求**，不要重述整个背景——它自己有上一轮的上下文。

## 结果怎么用

- 子 Agent 的回复是**给你看的**，不是给用户的：直接取用其中的结论与依据，不要原样转述给用户，更不要把它的过程流水账念一遍。
- 回复超过阈值会被自动摘要（全文落盘并在回复里给出路径）。需要细节时按路径取用，不要让它重跑一遍。
- 后台结果经 <task-notification> 到达；把它当作新事实并入当前判断，不要重复派同一个任务。

## 反模式警示（必须遵守）

- do NOT sleep, poll, or proactively check on the subagent's progress — 完成后系统自动通知
- Don't race — 派发后台任务后不要伪造或预测尚未到达的结果
- Don't peek — 不要主动读取子 Agent 的输出文件来查进度

## 并行执行多个子 Agent

依赖后台异步执行机制：
- 同步并行：在一次 assistant 消息中发起多个 subagent 工具调用（各自前台执行，结果直接返回）
- 后台并行：多次 runInBackground=true 调用，子 Agent 在后台并行执行，完成后自动通知
